`configs/sim2real/campaigns/abc12_2026-10-18.arms.json`. Everything not changed here follows

## Question

Do the friction-aware fine-tunes walk further toward the commanded distance on the real
GO2 than the incumbent, as the identified friction model predicts?

## Setup and sequence

- Free floor, level, no gantry or rope (`LIVE W vx03_4s ON FLOOR`), the setup of the
  2026-10-07 and 2026-10-17 walks. Spotter, clear 2 m radius, operator holds the deadman.
- One command for every trial: `vx03_4s` (vx 0.3 m/s for 4 s, 1.2 m commanded, 2 s lead-in,
  3 s tail). No other walking preset in this campaign.
- 12 blocks in the fixed order **A B C A C B C B A B C A**: four rounds, each a permutation
  of the three arms, no arm twice in a row, and the same sum of trial positions for every
  arm (22), so a linear battery or temperature trend is balanced across arms. Each block is
  `G` (5 s stand) then `W vx03_4s`. The STOP drill (Amendment 2) runs in each arm's last
  block (10, 11, 12).
- Ladder A-G for each arm in this campaign's own session directories before block 1.
- Battery: block start refused below 30 % (runner default; no override planned). If a
  block is refused, the remaining blocks are not run and the campaign is reported as is.
- At least 60 s between walks. The robot is re-centred on the start marks before each walk.

## Measurements per trial

- PRIMARY: tape forward displacement, floor marks under both rear feet at start and end,
  averaged, along the initial heading (m); tape lateral (m, + left). Entered by the operator
  or relayed verbatim by the agent (`answers_entered_by` in the run record). A value the
  agent enters without the operator's observation is not a measurement.
- IMU heading change over the walk (deg), from the policy log.
- Battery: state of charge from the harness check before each walk, pack voltage on every
  bridge tick (`sensors.power_v`).
- ESTIMATE, reported beside the tape and never in its place: kinematic leg odometry
  (`phoenix.sim2real.leg_odometry`). Validated on four model_2750 walks with tape before this
  campaign: odometry / tape = 0.853 +- 0.022, leave-one-out error <= 4.2 %
  (`results/hw_abc_2026-10-17/leg_odometry_validation.json`). Its ratio to tape is reported
  per arm, because the calibration so far covers arm A only.

## Analysis (fixed now)

    python3 scripts/gantry_ab_analyze.py --campaign <campaign.jsonl> --out <dir> \
        --remap logs/hw_sessions=logs/hw_sessions_orin --remap logs/gantry_ab=logs/hw_sessions_orin/gantry_ab
    python3 scripts/abc_compare.py --runs <dir>/runs.json --out <dir>/compare

Valid trials only (the analyzer's rules; first valid attempt per block). Per arm: mean, SD
and n of F = tape / commanded, forward error (commanded - tape), tape lateral drift, IMU
heading drift. B vs A and C vs A: difference of means of F with an exact two-sided
permutation p over all relabelings. With 4 trials per arm the smallest attainable p is
0.029.

Reading of the result (exploratory, n = 4 per arm):

- An arm "walked further than A" if its mean F exceeds A's by at least 0.10 and p <= 0.05,
  with no safety event in that arm.
- "No difference shown" otherwise. Fewer than 3 valid trials in an arm = INSUFFICIENT for
  that arm.
- Prediction check: per arm, hardware mean F against the MuJoCo prediction above.

## What this campaign may NOT do

- Use commanded distance, or the leg-odometry estimate, as the measured distance.
- Change the order, the command or the arms after the first trial.
- Re-run a started block (Amendment 2), or repeat a slot more than once.
